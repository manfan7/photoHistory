# Фотоархив — liquid glass photo history

Современный веб-фотоархив в стиле **Liquid Glass** (iOS): полупрозрачные «стеклянные»
панели, живой градиентный фон, плавные анимации. Приложение полностью анализирует
выбранную папку, извлекает дату съёмки из метаданных и раскладывает медиатеку по годам.

**Живая версия:** <https://manfan7.github.io/photoHistory/>

## Возможности

- 📂 **Выбор папки** — через File System Access API (Chrome/Edge) или ввод папки (Firefox/Safari).
  Выбранная папка запоминается — в следующий раз открывается одним кликом.
- 🔍 **Полный анализ** — рекурсивно сканируются все подпапки и файлы.
- 🧠 **Rust → WebAssembly** — ядро на Rust (kamadak-exif) читает EXIF каждого файла:
  `DateTimeOriginal → DateTimeDigitized → DateTime`, модель камеры, встроенные
  превью (для RAW/TIFF). Для видео MP4/MOV дата берётся из контейнера (`mvhd`).
- 🗓 **Группировка по годам** — красивые «стеклянные» заголовки с числом файлов,
  гистограммой по месяцам и быстрой навигацией по годам.
- 🖼 **Все форматы** — JPG/PNG/TIFF/RAW (CR2, NEF, ARW, DNG…), видео MP4/MOV/MKV…
  Форматы, которые браузер не декодирует, показываются через встроенные EXIF-превью
  или как аккуратные плитки с меткой формата. **HEIC/HEIF** (iPhone) декодируется
  через встроенный libheif (загружается лениво, только когда нужен).
- 🎬 **Просмотрщик** — полноэкранный lightbox с навигацией, камерой, датой и источником даты.
- ⚡ **Кэш метаданных** (IndexedDB) — повторное открытие папки происходит мгновенно.
- 🔒 **Приватность** — файлы никуда не загружаются, всё обрабатывается локально в браузере.

## Стек

| Слой | Технология |
|---|---|
| UI | Next.js 15 (static export), React 19, чистый CSS (liquid glass) |
| Ядро метаданных | Rust + wasm-bindgen + kamadak-exif (crate `photo_history_wasm`) |
| HEIC-декодер | libheif/libde265 (heic2any), ленивая загрузка |
| Десктоп | Tauri 2 (WebView2) — тот же фронтенд, встроенный в бинарник |
| Хостинг | GitHub Pages (деплой через GitHub Actions) |

## Десктоп-приложение (Tauri)

```bash
npm run tauri build     # соберёт out/ + нативный бинарник + NSIS-установщик
```

Готовые артефакты:
- `src-tauri/target/release/photoHistory.exe` — автономный бинарник (интерфейс встроен)
- `src-tauri/target/release/bundle/nsis/photoHistory_1.0.0_x64-setup.exe` — установщик

Для разработки с хот-релоадом: `npm run tauri dev`.

## Структура

```
app/            — Next.js App Router (страница, стили, иконка)
components/     — TopBar, EmptyState, ScanOverlay, YearSection, PhotoCard, Lightbox
lib/            — сканер, миниатюры, кэш, загрузчик WASM, форматы
wasm/           — Rust-крейт (EXIF + MP4-контейнеры)
public/demo/    — демо-архив с настоящими EXIF-датами
public/wasm/    — собранный WASM-бандл (commit-ится для сборки без Rust)
```

## Запуск

```bash
npm install
npm run wasm   # только при изменениях в wasm/: нужен Rust + wasm-pack
npm run dev    # http://localhost:3000
```

Продакшен-сборка (статический экспорт в `out/`):

```bash
npm run wasm
npm run build
npx serve out
```

Для сборки под GitHub Pages путь задаётся переменной окружения:

```bash
NEXT_PUBLIC_BASE_PATH=/photoHistory npm run build
```

## Как это работает

1. Пользователь выбирает папку (папка «Фотоархив» по умолчанию — но подойдёт любая).
2. Сканер обходит все подпапки, отбирая изображения и видео по расширению/MIME.
3. Для каждого файла читается головной фрагмент (2 МБ) и передаётся в WASM-ядро:
   EXIF → дата съёмки/камера/превью, иначе — `mvhd` контейнера MP4/MOV.
4. Если метаданных нет — берётся дата модификации файла.
5. Записи группируются по годам; миниатюры генерируются лениво через `createImageBitmap`
   / `<video>`-кадр / EXIF-превью и кэшируются в памяти.
